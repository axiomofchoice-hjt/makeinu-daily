## 1. 继承中的 public private 影响内存布局

```cpp
#include <iostream>

struct A1 {
   private:
    int x;
    int y;
    char o;
};

struct B1 : public A1 {
   public:
    char z;
};

struct A2 {
   public:
    int x;
    int y;
    char o;
};

struct B2 : public A2 {
   public:
    char z;
};

int main() {
    std::cout << sizeof(A1) << "\n";
    std::cout << sizeof(B1) << "\n";
    std::cout << sizeof(A2) << "\n";
    std::cout << sizeof(B2) << "\n";
}
```

GCC / Clang 输出 12 12 12 16，MSVC 输出 12 16 12 16。

首先 B1 和 B2 都不是标准布局。<https://zh.cppreference.com/w/cpp/language/classes> 有记载：

> 标准布局类是满足以下所有条件的类：
>
> - ...
> - 继承层级中仅有一个类具有非静态数据成员

B1 的继承层级有两个类有成员（即 A1 和 B1），B2 同理，不符合这个要求。

Itanium ABI 只规定了 POD 类型的布局（POD 和标准布局是等价的），所以这个问题编译器可以随意发挥。

***

public private 会影响内存布局，这个很反直觉啊。C++ 的坑太多了。

## 2. CRTP 基类不能用 requires 对子类模板做约束

```cpp
template <class T>
    requires requires(T obj) { obj.f(); }  // 报错
struct A {
};

struct B : A<B> {
    void f() {}
};
```

因为这个阶段 B 是不完整类型，需要把 requires 放进 A 的大括号里。

## 3. CRTP 有什么用
