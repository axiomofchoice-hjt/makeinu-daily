败犬日报是一个主要为 C++ 话题（也有其他话题）的知识库，我打算增加描述和整理话题。请输出一个 json 代码段（```json\n{ "description": $description, "__tags__": $__tags__ }\n```），$description 是一段简洁的描述，$__tags__ 是一个列表。

处理规则：

1. 对于文章的每个二级标题（以 "##" 开头的行）都输出且仅输出一个 $__tags__ 列表项。三级标题应视作二级标题的一部分
2. 每个列表项格式：`{"title": "$title", "score": "$score/10", "tags": [ "$tag", "$tag" ], "explanation": "$explanation"}`
3. $title：完整的原始二级标题文本（包含 "##"）
4. $score：1-10 的整数，表示推荐程度
5. $tags：应用以下标签规则，宁可多标不要漏标
6. $explanation：简要说明内容主题和标签理由

标签应用规则：

- 如果涉及 C++ 语言，必须包含 "C++" 标签
- 知识类话题必须在 {基础知识, 进阶知识, 专家知识} 中选择一个（不要不选或多选）
- 内容主观性强时加 "内容较主观"
- 涉及事实错误、不全面等问题时加 "需改进" 并在 explanation 中说明理由
- 不要加标签列表以外的标签

文本格式：$description 和 $explanation 需要在中文和非中文之间加空格（中文标点符号除外）。

特殊情况：如果没有二级标题，$description 固定为 "本期日报无话题收录"，$__tags__ 为空列表。

请严格按照 json 格式进行输出，例如字符串里的双引号前面加反斜杠。

标签罗列如下（标签名不包含括号）：

- C++
- 内容较主观
- 语法特性
- 标准库特性
- ABI
- 硬件相关
- 编译期（包括泛型、模板元、constexpr）
- 性能优化
- 预处理和宏
- 内存管理（例如 RAII、生存期所有权、智能指针）
- 类型（包括严格别名）
- 函数（包括重载决议，std::function）
- 面向对象编程（包括可访问性、继承、虚函数多态）
- 函数式编程（ranges）
- 泛型编程（用于泛型的模板，SFINAE，concepts）
- STL（标准库里的容器、算法、迭代器）
- 算法（例如排序的知识，可以不是 C++）
- 元编程
- 并发编程
- 错误处理（例如异常、错误码）
- 工程实践（例如设计模式、代码风格和规范）
- 编译构建和调试（例如包管理、cmake、gdb、编译参数）
- 基础知识（难度级别，低难度，C++ 程序员必会）
- 进阶知识（难度级别，中难度，写出更优秀的代码必会）
- 专家知识（难度级别，高难度，复杂，抠字眼，“语言律师”）
- 冷门知识（需要是非常冷门）
- 面试常见
- 搞笑（程序员笑话，meme，趣事，同事的逆天代码等）
- 其他（如果没有以上标签符合，加上“其他”）
- 需改进（该文章内容写的不够好，例如事实性错误、不够全面、错字、风格不符，在 explanation 里写详细的改进建议。注意：这里的“需改进”是指我提供的这篇文章本身需要改进，而不是文章中讨论的错误代码之类的具体内容需要改进）

样例输入：

```text
## 1. 性能是怎么分析的

性能分析是一套复杂的方法论……（此处省略若干文字）

### 1.1  profiling 工具

使用 perf 等工具进行性能分析……

### 1.2 基准测试

编写有意义的基准测试需要注意……
```
